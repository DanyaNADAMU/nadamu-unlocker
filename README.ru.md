# nadamu-unlocker

[ English ](README.md) • [ Русский ](README.ru.md) | [ 📖 Документация ](docs/ru/index.md)

> Сетевая разблокировка зашифрованного LUKS-ноутбука со смартфона на базе Android.
> Ноутбук запускает легковесный SSH-сервер (Dropbear) внутри initramfs (до расшифровки диска); телефон автоматически находит его в сети и передаёт пароль в именованный канал passfifo.

---

## Как это работает

```
┌─────────┐   SSH + пароль LUKS   ┌──────────────────────────────┐
│ Android │ ────────────────────► │ Ноутбук: Dropbear в initramfs│
│  клиент │                       │ → запись в /lib/cryptsetup/  │
└─────────┘                       │   passfifo → LUKS открыт     │
                                  └──────────────────────────────┘
```

Подробная спецификация протокола взаимодействия описана в [`docs/ru/unlock-flow.md`](docs/ru/unlock-flow.md).

## Быстрый старт (Тестовая лаборатория QEMU)

Требуется Docker или Podman с поддержкой KVM (`/dev/kvm`):

```sh
cd lab
docker compose up -d      # собирает initramfs + LUKS диск, запускает VM в QEMU
./run_tests.sh            # автоматический тест разблокировки от начала до конца
./ssh_lab.sh              # ручной вход по SSH в initramfs запущенной VM
```

## Модель безопасности

- Пароль диска передаётся исключительно по защищённому SSH-каналу; Dropbear в initramfs настроен с отключенной аутентификацией по паролю (`-s -j -k`), разрешён только вход по открытому SSH-ключу.
- Область initramfs по своей природе не зашифрована: любые секреты, зашитые в initramfs (PSK от Wi-Fi, ключи туннелей), изолированы так, чтобы их утечка не компрометировала сам LUKS-диск.
- На стороне Android-приложения поддержан импорт существующих SSH-ключей и генерация новых пар Ed25519.
