# Спецификация протокола разблокировки (Android-клиент ⇄ Initramfs ноутбука)

[ English ](../en/unlock-flow.md) • [ Русский ](unlock-flow.md)

> Единый источник правды (SSOT) для протокола сетевой разблокировки между Android-приложением
> (`android/`) и скриптами initramfs целевой машины (`laptop/`).
>
> Verified: 2026-09-06 (проверено тестами lab test_unlock.py, TOFU-пиннингом хост-ключей, адаптивным опросом маппера, структурированным логированием и кешированием IP по сетевым каналам)

## Краткий обзор

Android-приложение подключается по SSH (только по публичному ключу) к Dropbear в initramfs ноутбука, записывает пароль LUKS в именованный канал (FIFO), после чего опрашивает появление открытого маппер-устройства. Сам по себе факт успешной записи в FIFO НЕ является подтверждением разблокировки.

## Участники взаимодействия

| Сторона | Компонент | Роль |
|---|---|---|
| Телефон | `SshUnlocker` (SSHJ-клиент) | Подключение, авторизация по ключу, запись в passfifo, опрос маппера |
| Ноутбук | Dropbear в initramfs | SSH-сервер (только pubkey-аутентификация) |
| Ноутбук | cryptsetup в initramfs (`cryptroot`) | Чтение passfifo, запуск `cryptsetup open` |
| Ноутбук | `/bin/unlock` CLI | Помощник для ручной разблокировки в сессии SSH |

## Параметры подключения

- **Порт:** `22` (в тестовом lab-стенде проброшен на хост как порт `2222`).
- **Аутентификация:** Исключительно по открытому SSH-ключу. Dropbear запущен с флагами `-s -j -k` (без паролей, без проброса портов). Ключ клиента: предпочтительно Ed25519. Запись в `authorized_keys` ДОЛЖНА быть в формате OpenSSH (`ssh-ed25519 AAAA... comment`). В Android-клиенте на 1-ю позицию регистрируется криптопровайдер Bouncy Castle для поддержки X25519 и Ed25519.
- **Пиннинг хост-ключей:** Реализован механизм TOFU (Trust On First Use) с вычислением SHA-256 отпечатка ключа хоста, диалогом подтверждения и строгой проверкой при последующих подключениях для защиты от MitM-атак в публичных сетях.

## Передача пароля

Сырой пароль (без завершающего перевода строки `\n`) записывается в первый существующий канал passfifo:

1. `/lib/cryptsetup/passfifo`
2. `/run/cryptsetup/passfifo`

Команда для ручной отладки в консоли:

```sh
printf '%s' "$PASSPHRASE" > /lib/cryptsetup/passfifo
```

## Критерий успешности разблокировки

Успех подтверждается появлением открытого блочного устройства маппера в `/dev/mapper` (адаптивный опрос за исключением системного `control`, либо проверка конкретного целевого маппера):

```sh
MAPPERS=$(ls /dev/mapper 2>/dev/null | grep -v "^control$")
```

- Клиент опрашивает наличие устройства каждую 1 секунду (таймаут 15–30 с) после записи в FIFO. Код возврата команды записи в пайп не говорит о правильности пароля.
- При неверном пароле `cryptsetup` в initramfs продолжает ждать верный ввод; опрос маппера завершается по таймауту, и приложение сообщает об ошибке.

## Переход в основную систему (Pivot_root / Handoff)

Когда LUKS-том успешно расшифрован, скрипты initramfs завершают работу и передают управление ядру для монтирования корня. В этот момент сеть initramfs и Dropbear отключаются, а SSH-сессия разрывается. Клиент обязан трактовать состояние «соединение закрыто + маппер был обнаружен» как **УСПЕХ**, а не сетевую ошибку.

## Проверка в тестовом стенде

Тест `lab/test_unlock.py` реализует сквозную проверку:
1. Опрос готовности SSH-порта.
2. Отклонение неавторизованного ключа SSH.
3. Отклонение неверного пароля диска.
4. Доставка верного пароля, подтверждение появления маппера `/dev/mapper/test_crypt` и выключение VM.
